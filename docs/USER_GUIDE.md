# 使用指南

[返回 README](../README.md) · 适用于 v0.1.13 / Chrome 148+

## 安装、升级与版本确认

从 [v0.1.13 Release](https://github.com/CarGuo/gif-chrome-plugin/releases/tag/v0.1.13) 下载扩展 ZIP，解压后在 `chrome://extensions` 中开启开发者模式，再加载包含 `manifest.json` 的目录。源码安装则先按 [开发指南](DEVELOPMENT.md) 构建，再加载 `dist/`。

升级时保留原安装目录和扩展，在该目录更新文件并点击重载；刷新来源网页、关闭后重开侧栏，左上角应显示新版本。仅刷新网页不会让已打开的旧侧栏自动更新。不要在处理过程中重载扩展，也不要卸载重装，否则会连同已导入的本地视频一起清除。

旧版未版本化设置中的 12 fps 会一次性迁移为 10 fps；此后手动选择 12 fps 会保留。旧设置中的丢帧选项补为关闭。历史任务保持其原有帧率。

## 选择素材和片段

- 网页视频：先让播放器出现画面，再在目标媒体上右键「生成 GIF…」。也可点工具栏图标扫描页面。
- 本地视频：点制作页的「从电脑批量导入视频」，在文件选择框中一次选中一个或多个视频。扩展会读出每个视频的尺寸和时长，加入来源列表。本地视频直接读文件，不联网、不申请网络权限，断网也能用。
- 本地素材库：导入的视频会一直保留（关闭浏览器、重开都还在），可以反复用来生成 GIF。处理完成后清理有三种方式：在来源列表里点该视频卡片右侧的「×」单独删除；点列表下方的「清空全部已导入视频」一次性清空；也可以在选中素材后，在下方标题行点「移除导入」。删除会同时清除视频文件本身，已生成并保存的 GIF 不受影响。有任务正在用它生成时无法删除，等生成结束再操作；点「清空全部」时正在生成的视频会自动保留，其余照常清除。
- GIF / WebP：在图片上右键或从列表选择；需要编辑范围时，先点「读取动图，选择片段」。只读取已经加载或当前可发现的媒体。
- 多素材：勾选多个卡片。每个素材独立设置片段，速度和压缩参数共用。
- 多片段：点「添加片段」，调整各段起止时间；一段生成一个 GIF，不拼接。
- 默认范围：已知时长的素材选完整一轮 / 全部时长，不从播放头自动截取 5 秒。

原片段独立播放预览和真实缩略图帧条尚未实现；现有横条表示选区。完成后可以预览实际生成的 GIF。

## 速度与帧率

速度在「已选片段」顶部，支持 0.1–10×，提供 0.5× / 1× / 1.5× / 2× / 3× 快捷按钮。

例如原片段 20 秒，2× 输出约 10 秒；0.5× 输出约 40 秒。起止时间始终表示原视频时间。速度应用于所有本次选中的片段，不修改网页播放器的播放速度。

帧率在「压缩设置」内，默认 10 fps，可选 1–30 fps。更高帧率通常更流畅，也需要更多取帧时间和文件空间。GIF 延时精度为 10 毫秒；小数帧率间隔会按这个精度表示。

## 文件体积与尺寸

| 设置 | 默认 / 范围 | 说明 |
| --- | --- | --- |
| 文件上限 | 默认 4 MB；1 / 2 / 4 MB 预设 | 4 MB = 4,000,000 字节；最终按实际字节校验 |
| 最长边 | 默认 800 px，16–800 px | 等比例缩小；宽高都受上限约束，不放大小图 |
| 帧率 | 默认 10 fps，1–30 fps | 超限后的自动优化可能降低实际帧率 |
| 速度 | 默认 1×，0.1–10× | 成品时长约为所选原始时长 ÷ 倍速 |
| 丢帧 | 默认关闭 | 额外减少画面帧，保持倍速后的总时长 |

0.1.6 处理顺序为：下载媒体 → 建立倍速时间轴 → 抽样估算尺寸并缩小 → GIF 编码 → Gifsicle 优化 → 检查实际体积。必要时按实测体积修正尺寸，达到尺寸与优化下限后才自动降帧。显式选择的丢帧模式在尺寸和优化后执行。不会缩短所选范围；无法达标时明确失败。

## 丢帧

| 选项 | 保留方式 |
| --- | --- |
| 关闭（默认） | 不主动删除采样帧；超限后仍可能自动降帧 |
| 移除重复帧 | 仅合并连续相同的完整画面，包含透明区域；不同时间重新出现的画面会保留 |
| 每 2 帧移除第 2 帧 | 移除第 2、4、6…帧，保留约一半 |
| 每 3 帧移除第 3 帧 | 移除第 3、6、9…帧，保留约三分之二 |
| 每 4 帧移除第 4 帧 | 移除第 4、8、12…帧，保留约四分之三 |

删除帧的停留时间并入前一保留帧。这个操作不额外加速，但周期删除会降低动作流畅度。设置在提交生成任务后记住；从历史「调整片段」会恢复该任务的设置。

## X / YouTube 右键适配

如果右键只出现网站自带菜单：

1. 点击 Chrome 工具栏的 Gif Toolkit。
2. 在侧栏点「为此网站启用视频发现与右键菜单」，授予当前网站访问权限。
3. 刷新网页，让扩展在播放器注册右键事件前生效。
4. 在视频画面上右键；按住 Alt 再右键可使用网站原菜单。

正文、链接和播放器操作按钮保持原有行为。图片来自其他 CDN 时，读取原文件可能另外请求图片来源权限。

X 真实登录态完整流程、Shorts 和跨域 iframe 仍待专项验收；不要把页面结构测试通过理解为所有平台页面都已支持。

## 文件名、历史和下载

生成前可编辑每个素材的「GIF 名称」，成品卡片保存前也可改名。X 优先使用媒体所属帖子的正文，其他网页使用有意义的媒体标题、说明或页面标题。同页多个素材标题相同时，默认名称会加上「素材 01」「素材 02」等前缀，便于区分。

磁盘文件名为：

```text
Base64url(标题前缀)_生成时间戳_任务唯一编号.gif
```

标题先按完整 UTF-8 字符截取到最多 72 字节再编码；使用 Base64url 避免 `/` 等路径字符，不含中文、空格、`+` 或 `=`。生成时间为任务创建时的 Unix 毫秒数，每个新任务有独立编号；重复下载或改名保存不会改变生成时间。界面继续显示完整可读标题。

默认下载目录为 Chrome 下载目录下的 `GifToolkit/`。选择「另存为」可更改保存位置。浏览器自身的下载设置可能改变保存提示行为。

**Your GIFs / 你的 GIF** 和历史结果均有独立的滚动区域，顶部保存工具栏保持在列表外。每张保留文件的完成卡片可单独「保存 GIF」；也可勾选其中几项，再点「保存所选」。全选只选择当前列表内可保存的结果；被搜索隐藏、删除或清理的文件会退出选择。

批量保存开始后交由后台继续，关闭侧栏不影响已提交的批次。提示会区分已交给浏览器下载的数量和未能开始的数量；失败提示逐项显示名称和原因；空名称或某一文件保存失败不影响其他项，失败项保留勾选，具体下载完成状态见 Chrome 下载管理器。多个任务即使手动设为同名，实际文件名仍由各自的任务 ID 区分；重复保存同一任务时 Chrome 会生成新文件名，不覆盖原文件。

关闭侧栏后任务继续处理。所有视频下载后独立解码；下载会话建立期间保持来源页面打开。保留最近 30 个已结束任务及成品。退出浏览器、重载扩展或崩溃中断的任务需要重新生成。

点击侧栏顶部的**历史记录**即可查看，即使当前页面没有素材也可使用。支持按名称 / 来源网站搜索、按状态筛选，显示生成时间并可打开原页面。保留文件的历史任务可预览、保存或逐条删除。

v0.1.11 起，损坏的历史记录会单独显示错误，仍可删除；其他历史、生成和清理功能继续工作。扩展保留损坏记录供你查看和删除，不自动重置其参数；它们不计入最近 30 条正常历史的自动裁剪。Worker 无响应时会终止对应任务并继续队列，界面显示处理超时。

- **清理缓存**：按实际文件大小显示占用，清理扩展内保留的 GIF 文件，历史和参数仍在。确认中明确列出文件数和体积；清理后显示“文件已清理”，需从来源重新生成才能再次预览或保存。
- **清空历史**：删除确认时已有的已结束任务及对应文件。正在生成 / 排队的任务和确认期间产生的新任务不会删除。
- 两种操作都不删除已保存到电脑的文件，不重置导出设置，也不清除其他网站或 Chrome 的全局缓存。网页视频的处理临时数据在任务结束后自动释放；导入的本地视频不会因清理历史而删除，需要单独点「移除导入」。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 导入的视频找不到了 | 在制作页点「从电脑批量导入视频」重新选择；扩展无法读取你没导入过的文件 |
| 「×」或「移除导入」点不动 | 该视频正在生成 GIF，等任务结束或取消后再删除 |
| 想一次删掉所有导入的视频 | 点来源列表下方的「清空全部已导入视频」；正在生成的会自动保留 |
| 担心导入视频占空间 | 它们存在扩展本地存储中，单文件上限 128 MiB；不用的视频点卡片上的「×」即可释放 |
| 界面还是旧版本 | 重载扩展，刷新来源页面，再重开侧栏；检查左上角版本 |
| 找不到视频 | 先播放出画面，再扫描；懒加载媒体需先滚动到所在位置 |
| 提示超过帧数预算 | 单段最多 600 个调速后的采样帧；提高倍速、降低帧率或缩短选区；额外丢帧不能跳过前期采样预算 |
| 媒体下载 / 权限失败 | 检查是否允许媒体来源、公开嵌入接口或 CDN；原站拒绝请求、过期链接等仍可能失败 |
| 内嵌播放器未发现 | 先点网页播放，再扫描；按提示授予内嵌播放器来源访问权限 |
| 尚未发现下载会话 | 为当前网站启用视频发现，刷新并播放后重新扫描；不会改用网页取帧 |
| 来源已改变 | 网页复用了播放器节点或已经导航；重新扫描、选择新素材 |
| 无法读取像素 | 播放器跨域策略或 DRM 可能阻止导出；扩展不会绕过这些限制 |
| 文件仍无法达到限制 | 该画面的复杂度超出搜索范围；提高文件上限或自行降低参数 |
| 透明 WebP 边缘变化 | GIF 仅支持二值透明，不能完整表达 WebP 的半透明像素 |

反馈问题时提供 Chrome / 扩展版本、素材类型、所选范围、速度 / 帧率 / 体积参数、错误提示和可公开的复现链接。不要上传 token、Cookie 或私人媒体。

0.1.7 将媒体获取统一为完整下载。HLS/DASH 会合并分片；文件 Blob 从所属页面读取。Vimeo 等跨域 iframe 需单独授权播放器域名。同页多个来源无法可靠关联时会显示视频流选择，不能任意选第一个请求。HLS/DASH 的分片可跨 CDN，生成时 Chrome 会请求 HTTP/HTTPS 来源权限，可在扩展设置撤销。

0.1.8 起，多档视频选择最长边不超过设置上限的最大档；例如上限 800、可选 432 / 576 / 1152 时下载 576 档，并且不会放大到 800。仅当全部档位都超限或只有单一大尺寸文件时，才下载原文件后缩小。默认完整选区按下载文件的真实结尾生成；修改结束时间后会按手动范围校验。网页显示的时长和文件略有差别，不再使默认完整选区失败。
