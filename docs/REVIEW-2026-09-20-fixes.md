- 九组浏览器回归全部通过：`test:transports`、`test:e2e`、`test:download`、`test:drop-frames`、`test:preferences`、`test:history`、`test:results`、`test:reliability`、`test:context-menu`。默认运行锁定的 Chromium 148，新增故障恢复脚本已加入 CI。

**深度交互**

本轮解决“单项失败影响其他工作”和“失败原因不可辨认”，不能据此将原 Review 全部关闭。仍待处理：

- 来源关联、授权与凭据边界（#1），动图探测的来源校验和取消（#9）。网页声明仍是不可信输入，换成闭包不足以解决。
- 保存批次接受时点、清理竞争、下载引用生命周期和异常恢复（#4 / #7 / #28）。当前仍为逐项接受；已提交给 Chrome 的文件有独立引用，尚未读取的项目可能被用户清理。
- 同一素材跨扫描 / 跨 frame 的默认名称稳定性（#8），统一 RPC 类型契约（#20）。
- 编码 / 优化性能建议需用阶段指标实测；不采用反复压缩上一轮有损 GIF 的方案。其余低优先级建议和误报沿用逐项复核结论。

下一批应围绕媒体身份和保存引用生命周期分别推进，不把网络、编码、UI 和发行状态合成一次重写。现有安装仍需在合适时机更新目录、重载扩展并刷新来源页面；此前登录态 X、YouTube 完整下载及 Shorts 验收缺口未在本轮关闭。
